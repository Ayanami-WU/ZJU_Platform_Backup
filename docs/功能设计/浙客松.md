# 浙客松设计

这是[产品蓝图](../产品蓝图.md)中赛事业务的完整展开，定义同一套网站框架怎样承载不同届次。实际实现和验收范围见[产品状态](../产品状态.md#浙客松)。

## 内容设计

### 一场赛事由什么构成

| 内容             | 组成及含义                                                                       |
| ---------------- | -------------------------------------------------------------------------------- |
| 赛事基本信息     | 稳定届次标识、名称、介绍、日期、地点、状态、主视觉、合作方与联系方式             |
| 赛程与阶段       | 报名、赛题发布、提交、评审、成果发布等时间与开关；以当届配置为准                 |
| 赛道、赛题与论坛 | 各赛道的任务和提交要求；论坛的主题、嘉宾、时间、地点及分享内容。论坛不等同于赛道 |
| 报名             | 当届要求的个人、邮箱、团队、赛道等字段，账号、提交状态和报名结果                 |
| 参赛作品         | 当届提交快照、作者/团队、介绍、仓库、独立部署链接、公开授权、审核及精选状态      |
| 图片与视频       | 媒体本体、审核信息、当届关联、分类、时间、说明，以及直播归档/成果精选用途        |
| 赛后成果         | 正式获奖名单、精选作品、现场与合影、嘉宾讲话、论坛分享、赛事总结                 |

第一届“AI 全栈极速黑客松”按历史赛事保存，报名关闭；第二届“AI+X 破界黑客松”有独立信息、赛道、论坛和赛程。第一届的个人参赛、时长等规则不能成为第二届的默认事实。首届赛题按现场 PPT 保留教材加载、知识图谱、跨教材整合、30% 精华压缩和教师反馈要求；首届合作方使用当届确认名单，不继承整个生态的合作关系。缺少资料时保持未配置，不用宣传文案补造。

6 月 7 日每日互动美妆联谊赛作为独立历史赛事保存，稳定入口为 `/hackathon/getui-beauty`，不改变已有 `/1`、`/2` 的归属。介绍保留地点、时间、当场赛制及组织关系；赛题提供肌肤分析与护肤推荐要求、30%/30%/40% 评分标准和原始资料下载。开发限时三小时，随后演示评审，个人或 2–4 人组队；不继承首届的个人赛、五小时或零路演规则。原始材料没有作品名册时不推断获奖姓名，不以现场照片替代作品记录。组织关系以用户确认为准：拓浙 AI 生态主办、每日互动承办、摇滚动物园与个知赞助，海报底部所列 6 家单位为联合主办。

报名、作品、奖项与媒体按届次归属；历史记录不因切换当前赛事而重新归属。长期项目与参赛快照不同，作品无需先创建长期项目，后续明确关联时才写入 `project_id`。仓库链接与部署链接分开，缺失部署证据就显示缺失，不从 GitHub 推断。

## 逻辑设计

### 赛程变化与稳定页面

页面职责固定为 **介绍—赛题—图片/视频—成果**。赛程改变内容、状态和可用操作，不每天更换导航结构。

| 阶段 | 介绍与报名                                       | 赛题                                           | 图片/视频                | 成果                                   |
| ---- | ------------------------------------------------ | ---------------------------------------------- | ------------------------ | -------------------------------------- |
| 赛前 | 已公布信息与报名要求；按开关接受报名             | 公布赛道和已发布要求；未发布内容明确提示       | 已审核的赛前影像或空状态 | 未发布提示                             |
| 赛中 | 持续提供日程、地点与规则；按截止状态显示报名结果 | 已发布赛题、提交要求、当前提交状态与允许的操作 | 本场最新现场图片和视频   | 仅显示已正式发布内容                   |
| 赛后 | 保留介绍与当届历史信息，报名截止                 | 保留已发布赛题和提交记录，按状态关闭提交       | 保留当届影像档案         | 后台发布获奖名单、精选作品、分享与总结 |

“比赛结束”与“成果发布”是两个状态，时间到点不自动把未审核内容公开。历史赛事沿用自己的内容和状态，新一届上线不覆盖上一届。

### 报名与提交

报名表位于介绍页内，顶部和其他栏目中的报名操作都回到该表单。填写开放赛事报名表前须登录并完成账号注册资料（姓名、学号、专业、年级）；旧账号缺少资料时先补齐，再展开赛事表单。四项信息由账号带入，提供修改入口，不重复填写；服务器使用账号资料生成本次参赛快照，后续修改账号资料不改变历史报名。失败不应无故丢失输入。成功后读取正式报名结果，刷新可恢复，重复提交返回已有记录，退出账号清除账号相关状态。

AI+X 内容以用户最新确认的页面方案为准，奖项等细节参考活动文书。对外赛道为「天猫·OPC孵化赛道」「华为·产业进阶赛道」，保留 campus / industry 内部值及历史报名。10 月 13 日天猫线上开启，18 日华为线下开启，19—23 日线上复赛，25 日决赛。复赛配置截至 23 日结束（24 日 00:00），不再沿用 22 日截止与 23 日公布名单的旧节点。初赛在紫金港校区段永平教学楼 2-112；决赛及创业论坛在浙江大学国家级双创示范基地·三墩元空间（宝港生活广场 C 座 6 楼）。

两条赛道均为 1—5 人组队。天猫可线上参赛，优先招募成熟、可落地项目；18 日 13:00—17:00 提供可选现场技术指导，技术可行性过关进入复赛。华为初赛必须线下，18 日 13:00 发布命题，开发 Agent 或 Skill，17:00 截止，完成度达到 60% 晋级，当晚 22:00 公布名单，复赛选出 10 个决赛项目。25 日 9:10—11:30 两厅同步路演，兼报选手错开出场，分别评审、统一颁奖。

天猫 6 个获奖团队共 6,500 元：冠军 1 队 3,000 元、亚军 2 队各 1,000 元、季军 3 队各 500 元，另有周边和证书。华为奖品与奖金 14,980 元，合计 21,480 元；天猫 3,500 元物料预算不计入奖池。魔搭 130 份礼品用于现场抽奖；已发布线上转发抽奖保持独立入口和运营规则。

赛事与论坛分开报名。每位选手登录后使用共用姓名、学号、专业、年级资料，可兼报赛道，项目经历与科研经历必填，选填队伍名称；两条赛道均须填写包含本人的 1—5 人队伍规模。这里只保存参赛快照，不按同名队伍推测成员关系。已有报名、仓库、发布赛题和其他赛事不被迁移覆盖。真实赛事表单保持标题与提交区常驻、字段独立滚动，手机输入字号至少 16px，提交区避开底栏。新群二维码不继承旧过期日期。介绍页删除首页重复报名、赛题、论坛与抽奖入口及说明性副文案；顶部报名采用荧光绿实底，抽奖采用强调色边框，保持持续可见。

论坛页为 `/hackathon/2/forums`：技术论坛 18 日 9:00—11:15；决赛暨创业论坛 25 日 9:00—17:00，上午路演、下午论坛。华为初赛选手须参加技术论坛，决赛选手必须参加决赛论坛。论坛面向校内外公众，可创建普通账号而不填写学生学号；赛事报名仍校验完整参赛资料。登录后填写姓名、手机号码或邮箱、选填学校或单位，选择一场或两场。开场截止报名，回执刷新恢复，重复提交更新同一账号同一场次记录，开场前可取消单场。管理员在论坛页导出 CSV，名单和联系信息不公开。签到后续另做，报名不代表已到场。

AI+X 报名成功后在介绍页显示报名编号与已保存信息，主操作前往「赛题与提交」页的「我的提交」。GitHub 与魔搭社区两个仓库入口集中在该页，避免在两个页面重复编辑。可先提交一个、稍后补充另一个，赛事结束前可更新；结束后保留已提交内容只读。接受 GitHub 仓库首页及魔搭创空间、模型或数据集的 HTTPS 地址，拒绝其他域名、带凭据及查询参数的地址。仓库地址绑定本届报名与本人账号，重新登录可恢复，仅本人及有报名管理权限的管理员可读取；后台查看、CSV 导出包含两个地址和更新时间。此处保存参赛仓库，不自动创建项目或公开作品。

报名、赛题发布、作品提交及成果发布各自有配置与权限判断。用户看到自己的提交状态，管理员看到当届完整报名和作品列表。前台不会因为用户成功投稿就把该作品公开。

赛题页参考首届的信息层次，选择赛道后只显示该赛道内容。千问区分自主选题指导与正式发布赛题，华为按阶段切换；赛题状态区分待发布、已发布、阶段结束和赛事结束，未发布内容不伪造。提交区区分读取中、读取失败可重试、未登录、未报名、尚未提交、已保存仓库数、未保存修改和截止只读；失败保留输入，保存成功只在服务器确认后出现。

### 作品、获奖与影像

公开作品需满足：**审核通过 + 同意公开 + 后台精选 + 当届成果已发布 + 未删除**。历史作品默认不自动精选；撤销精选或驳回后，从所有公开投影中同步退出。所有作品供有权限的后台管理，前台成果页只展示允许公开的精选。

获奖名单来自真实奖项记录；精选顺序与获奖名次分开。分享海报、个人公开作品和赛事成果查询采用一致发布条件，不能通过换入口绕过。

首届 `/hackathon/1/results` 专属 5 月 10 日 AI 全栈极速黑客松，不能混入 AI+X 赛事内容。保留当前全站导航、赛事切换及四栏目框架，内部直接复用历史 `HackathonOutcomeShowcase` 原版源码与资源；首届主片恢复明确绑定的原宣传片，错误主片降为普通档案，文件不删除。新视频投稿默认普通档案，只有管理员明确指定才成为主片。原布局样式保持，通过独立类名隔离后续主题覆盖，只调整双层导航间距、当届资料与现行链接。原版四段为 **赛事总览—现场档案—作品与荣誉—共同见证**：大字赛事标题与斜切影像；各段 X 背景和现场照片；前三名横排、选中作品详情与可滚动作品目录；支持单位阵容。全部 21 件公开作品可搜索、按奖项筛选及通过深链选中；只有实际前三名显示名次，其余按奖项分组。详情保留安全的仓库和参赛部署地址、原文附件及可展开的作者经验；无封面或附件时不补造资料。共同见证使用已确认首届 PPT 名单。美妆与 AI+X 继续各自独立数据与发布状态，本轮不套用首届恢复结果。首届介绍第四屏保留原报名表，结束后说明其为历史信息，并关闭提交。

照片保留一份媒体本体，通过当届关系进入直播归档或成果精选。选为成果不复制文件，也不破坏原归档。未关联媒体和旧媒体记录须先核验归属及当前引用，再决定迁移；不能因有旧表就删除记录。

### 后台怎样管理全流程

| 管理内容   | 操作与结果                                                         |
| ---------- | ------------------------------------------------------------------ |
| 赛事设置   | 维护当届基本信息、赛道、论坛、日程、页面开关及表单；预览后明确发布 |
| 报名       | 查看、筛选与处理当届报名；个人信息按后台权限保护                   |
| 赛题与作品 | 发布赛题与提交规则，查看、审核所有提交，维护正式归属               |
| 图片与视频 | 上传或关联已有媒体，审核、分类、排序与选择精选                     |
| 奖项与成果 | 维护名单、名次、讲话/论坛/总结、精选作品及成果发布开关             |

本地草稿、代码默认配置与生产发布分别处理。修改第二届模板不自动发布第二届、切换生产当前赛事或迁移第一届数据。

## 交互设计

### 框架与视觉

保留网站全局导航，首届赛事内部使用二级 tab；移除左侧常驻赛事栏。首届顶部使用赛事选择器、四个栏目和当届报名状态。选择器显示名称、日期和状态，支持上下键、Esc 和点击外部关闭。

AI+X 介绍页采用六屏翻页：主页—赛制—奖励—论坛—合作—报名。主页标题按“浙客松： / AI+X破界黑客松”分两行，标题与 ¥21,480 奖励总值集中排列，右侧为像素 X，底部为两场活动信息容器；赛制为两条横向时间轴，天猫与华为的相同日期上下对齐，奖励采用天猫、华为、魔搭三个容器。论坛采用左右约 45:55 的两个容器，技术论坛在左、创业论坛在右，手机上下排列；各自展示主题、嘉宾照片与主要身份、分享内容、日期地点及独立报名入口，不展示具体议程表。创业论坛嘉宾按群公告顺序排列为张克俊、张洁、王进、刘建斌、窦明清、张加林、王非凡；技术论坛展示叶新江、孙逸飞，并预告华为与阿里专家。照片使用 AI生态/嘉宾 中已提供素材，缺少照片保留空位；徐松波仍作为评委素材，不自动归入论坛嘉宾。论坛入口预选所点击场次。合作阵容保留指导与主办署名，合作企业、合作组织及平台各一个 Logo 容器，包含用户提供海报中的社团。报名采用单个主体面板，账号资料、参赛信息、能力与经历、作品链接依次排列；项目及科研经历必填，二维码由标题右侧赛事群按钮打开。页码、滚轮、键盘和触屏支持翻页，页内内容超高时先内部滚动，表单字段独立滚动且标题、提交区固定。四个赛事栏目与右上角报名、抽奖操作持续可见。成果须正式发布才公开；第一届保留历史内容及原四屏。

介绍页包含主视觉与基本信息、赛事说明与规则、日程/赛道/论坛、合作方与参与入口，报名按内容需要在页内展开。合作区按活动已确认名单展示，天猫校园、华为、阿里云、Qoder、魔搭使用站内正式 Logo 并兼容深浅主题；没有确认素材的单位保留完整名称，不补造标识。

赛题页首屏沿用介绍页的大标题、留白与双栏面板，右侧可切换任务步骤或赛道；完整要求区域以任务步骤为主栏，交付、评分和资料为辅助栏；较窄屏幕按阅读顺序合并为单栏。AI+X 天猫赛道 10 月 13 日线上开启，华为赛道 18 日线下开启，两条赛道 19—23 日线上复赛、25 日决赛；未发布的赛题和提交入口继续关闭。华为初赛命题与开发于 18 日 13:00 开启，后台勾选发布的命题和指定提交入口按正式配置开放；草稿不会因时间到点自动公开。赛题页表达本阶段开放内容与提交状态；现场照片页直接恢复直角化前的完整 `Gallery` 页面及看图弹层，分类栏复用 `415ae0b4a` 的展开分类交互并适配圆角，不重新拼装页面。保留原背景光晕、圆角和照片自然比例瀑布流；移除与赛事导航重复的页内大标题、小标题及大幅留白。顶部直接显示场景分类和明确的「批量上传照片」按钮，滚动时停留在赛事导航下方，切换场景回到照片区开头。栏目统一使用「现场照片」，仅展示和上传照片，不提供视频切换或视频上传入口；已有视频记录和文件保留。未开赛显示照片待发布状态，历史赛事无照片时显示暂无已发布照片，避免重复标题与全站摄影文案。各届共用模板，但只读取当届照片；场景以展开按钮切换，默认按场景标题分区，每区使用旧版圆角自然比例瀑布流，按可用列数分配照片以避免小分组右侧空列，分区标明照片数量（尚有分页时标明已加载数量），首届按致辞、开发、交流、颁奖顺序组织；分类、最新/精选与查看器保持轻量；首届历史影像遵循人工编排顺序，照片支持深链打开与键盘切换，大图同时显示场景及当前浏览序号。批量上传绑定当前赛事，可追加选图、预览、移除，最多 24 张且超限明确提示；批次标题可选，未填写时使用文件名。场景可从本届已有场景中选择，默认当前筛选场景；逐张显示上传与保存状态，只重试尚未成功的照片，保留审核流程；成果页汇集奖项、精选作品和赛后材料。作品详情属于当届成果，不另建项目中心。

| `/hackathon/2/forums`     | 独立论坛介绍、到场要求与报名                             |
| `/hackathon/2/challenges` | 第二届赛道切换、赛题与我的提交；`#submission` 定位提交区 |

只支持现行赛事路径；旧 `event/view/competition` 查询式赛事链接和 `showcase/works/projects` 别名不恢复。未知赛事或栏目显示未找到；作品和照片选择使用 `work/photo/mediaView` 等详情参数，媒体内部切换不占用外层栏目参数。论坛页切换其他赛事回到介绍；其他赛事切换保留栏目，清理旧作品、照片和弹层选择。独立 `/media?event=<slug>` 保留影像档案用途。

手机通过顶部“更多”菜单进入浙客松，所有现行赛事栏目支持直接访问；页面按容器宽度自适应，不能仅按一张桌面稿固定像素。内容高度扣除全局导航与底栏，低高度窗口允许自然滚动，定位报名避免标题被固定导航遮挡；检查 `320/390/820/1280/1440px` 及窄高、低高场景。日夜主题共用结构，首帧尊重减少动态效果，不能留下透明内容。

### 应验证的用户结果

- 不同届次的介绍、报名、赛题和成果不会串用；关闭或未发布内容无法通过深链绕过。
- 未登录或注册资料不完整时不能填写或提交赛事报名；资料保存后展开报名表，失败可重试，成功和刷新显示已有结果，重复请求可恢复，退出清空。
- 后台能管理完整报名/提交；公开入口只显示通过全部发布条件的内容，撤回后同步消失。
- 赛事切换、栏目返回、媒体查看与分享打开正确对象；空赛事、未关联媒体、加载失败有明确反馈。
- 全站导航、报名锚点、日夜主题和受影响尺寸实测通过。具体完成范围见状态文档。

## 技术设计

共享入口为 `HackathonEventRouter → HackathonWorkspace → HackathonEventContent`，复用 `HackathonRegistration` 与 `hackathon-event/` 组件。开发和生产采用同一入口，避免主题与数据读取分叉。

`shared/hackathonRoutes.json` 供前后端生成稳定路径；`settings.hackathon_schedule_config` 是日程配置真源，`shared/hackathonTemplateDefaults.json` 只提供代码默认值。发布同步赛事档案及必要旧设置投影，读取和写入均带明确届次标识。

`hackathon_forum_registrations` 按 event_key / user_id / forum_key 唯一保存私有论坛报名。正式迁移幂等建表，接口读取本人、原子保存所选场次、取消本人单场；管理员名单独立鉴权，响应 no-store。开闭时间来自共享 `hackathonForums.json`，服务端执行身份和截止验证。论坛账号不填学生资料，不授予管理员权限；之后赛事报名仍要求完整参赛资料。

`competition_works` 保存当届仓库和可空 HTTPS 部署证据；同一项目可参加多届，同一届只保留一条有效项目关联。`competitionWorkSelection` 正式迁移幂等增加 `featured`，默认 `0`，不自动精选旧记录。后台精选接口验证审核与公开授权，记录审计；驳回同步取消精选。

`competitionPublication.resultsPublishedSql` 把 `resultsVisible` 一致用于赛事、项目快照和公开个人作品查询。公开条件由后端执行，前端隐藏卡片不能代替它。

图片本体保存在 `photos`，`competition_media_links` 以 `archive/highlight` 表达当届归档与精选用途，影像通过受控嵌入复用媒体能力。旧 `competition_media` 的处理需以实际引用和数据核验为前提。报名、媒体上传和发布沿用账号、审核、审计与正式迁移，不新增孤立身份或存储体系。
