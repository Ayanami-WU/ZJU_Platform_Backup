# 浙客松设计

这是[产品蓝图](../产品蓝图.md)中赛事业务的完整展开，定义同一套网站框架怎样承载不同届次。实际实现和验收范围见[产品状态](../产品状态.md#浙客松)。

## 内容设计

### 一场赛事由什么构成

| 内容             | 组成及含义                                                                       |
| ---------------- | -------------------------------------------------------------------------------- |
| 赛事基本信息     | 稳定届次标识、名称、介绍、日期、地点、状态、主视觉、合作方与联系方式             |
| 赛程与阶段       | 报名、赛题发布、提交、评审、成果发布等时间与开关；以当届配置为准                 |
| 赛道、赛题与论坛 | 各赛道的任务和提交要求；论坛的主题、嘉宾、时间、地点及分享内容。论坛不等同于赛道 |
| 报名             | 当届要求的个人、邮箱、团队、赛道等字段，账号、提交状态和报名结果                 |
| 参赛作品         | 当届提交快照、作者/团队、介绍、仓库、独立部署链接、公开授权、审核及精选状态      |
| 图片与视频       | 媒体本体、审核信息、当届关联、分类、时间、说明，以及直播归档/成果精选用途        |
| 赛后成果         | 正式获奖名单、精选作品、现场与合影、嘉宾讲话、论坛分享、赛事总结                 |

第一届“AI 全栈极速黑客松”按历史赛事保存，报名关闭；第二届“AI+X 破界黑客松”有独立信息、赛道、论坛和赛程。第一届的个人参赛、时长等规则不能成为第二届的默认事实。首届赛题按现场 PPT 保留教材加载、知识图谱、跨教材整合、30% 精华压缩和教师反馈要求；首届合作方使用当届确认名单，不继承整个生态的合作关系。缺少资料时保持未配置，不用宣传文案补造。

6 月 7 日每日互动美妆联谊赛作为独立历史赛事保存，稳定入口为 `/hackathon/getui-beauty`，不改变已有 `/1`、`/2` 的归属。介绍保留地点、时间、当场赛制及组织关系；赛题提供肌肤分析与护肤推荐要求、30%/30%/40% 评分标准和原始资料下载。开发限时三小时，随后演示评审，个人或 2–4 人组队；不继承首届的个人赛、五小时或零路演规则。原始材料没有作品名册时不推断获奖姓名，不以现场照片替代作品记录。组织关系以用户确认为准：拓浙 AI 生态主办、每日互动承办、摇滚动物园与个知赞助，海报底部所列 6 家单位为联合主办。

报名、作品、奖项与媒体按届次归属；历史记录不因切换当前赛事而重新归属。长期项目与参赛快照不同，作品无需先创建长期项目，后续明确关联时才写入 `project_id`。仓库链接与部署链接分开，缺失部署证据就显示缺失，不从 GitHub 推断。

## 逻辑设计

### 复赛晋级通知

华为复赛晋级按已核实的成员账号逐一授予，提交人及同队队友均须明确列入名单；不以相似队名、同名作品、仓库地址或空队名推定归属。后台通过文件或粘贴导入私有 JSON 成员清单（`members` 中逐人提供 `studentId`、`name`、`teamName`），先预览，再确认批量授予。服务端要求唯一有效华为报名、学号、姓名和原报名队名精确一致；预览后信息变化须重新核对，整批事务写入，不自动撤销其他资格。清单与核对证据保存在私有目录，不提交公开代码库。

已获华为复赛资格的选手登录后进入当届浙客松任一页面，首次自动显示大幅“恭喜你进入复赛”弹窗，含本人报名队名、复赛截止时间及复赛要求/提交入口；关闭后保留“已晋级复赛”按钮，可再次查看。同一账号同一次资格确认在当前浏览器确认后不反复弹出；重新授予资格后可再次通知。未登录、未晋级、其他赛事及资格已撤销账号不显示；资格从鉴权接口读取，不在公开前端内置名单。

### 赛程变化与稳定页面

页面职责固定为 **介绍—赛题—图片/视频—成果**。赛程改变内容、状态和可用操作，不每天更换导航结构。

| 阶段 | 介绍与报名                                       | 赛题                                           | 图片/视频                | 成果                                   |
| ---- | ------------------------------------------------ | ---------------------------------------------- | ------------------------ | -------------------------------------- |
| 赛前 | 已公布信息与报名要求；按开关接受报名             | 公布赛道和已发布要求；未发布内容明确提示       | 已审核的赛前影像或空状态 | 未发布提示                             |
| 赛中 | 持续提供日程、地点与规则；按截止状态显示报名结果 | 已发布赛题、提交要求、当前提交状态与允许的操作 | 本场最新现场图片和视频   | 仅显示已正式发布内容                   |
| 赛后 | 保留介绍与当届历史信息，报名截止                 | 保留已发布赛题和提交记录，按状态关闭提交       | 保留当届影像档案         | 后台发布获奖名单、精选作品、分享与总结 |

“比赛结束”与“成果发布”是两个状态，时间到点不自动把未审核内容公开。历史赛事沿用自己的内容和状态，新一届上线不覆盖上一届。

### 报名与提交

AI+X 两条赛道分别设置报名开关与截止时间；未配置赛道截止时间时沿用赛事统一截止时间。赛事报名总开关、入口可见性、开放时间和结束时间仍共同约束报名。任一赛道开放时保留报名入口，表单与赛题页按所选赛道显示状态；服务器对新增、修改和撤销报名执行相同的赛道限制，兼报请求中有关闭赛道时整体拒绝，不改变另一赛道及历史作品、晋级记录。

报名表位于介绍页内，顶部和其他栏目中的报名操作都回到该表单。填写开放赛事报名表前须登录并完成账号注册资料（姓名、学号、专业、年级）；旧账号缺少资料时先补齐，再展开赛事表单。四项信息由账号带入，提供修改入口，不重复填写；服务器使用账号资料生成本次参赛快照，后续修改账号资料不改变历史报名。失败不应无故丢失输入。成功后读取正式报名结果，刷新可恢复，重复提交返回已有记录，退出账号清除账号相关状态。

AI+X 内容以用户最新确认的页面方案与活动文书为准。对外赛道为「天猫OPC孵化赛道」「华为产业落地赛道」，赛制页分别显示「自由命题」「企业命题」，保留 campus / industry 内部值及历史报名。天猫 10 月 13 日开始初赛，18—20 日线上提交技术作品、BP 和 Demo，20 日 23:00 截止；21—22 日评审，22 日 23:00 公布决赛名单，25 日决赛，不再单列指导或复赛提交。华为 18 日 13:00—17:00 在浙江大学紫金港校区北2-227现场初赛（上午技术论坛仍在段永平教学楼2-112），当日 22:00 公布复赛名单；19—23 日线上复赛，23 日 24:00 截止；25 日决赛。18日上午技术论坛在紫金港校区段永平教学楼2-112，下午初赛开发在北2-227；决赛及创业论坛在三墩元空间（宝港生活广场 C 座 6 楼）。

两赛道沿用当前报名组队规则。天猫可线上自由命题，优先招募成熟、可落地项目，初赛后直接评审并确定决赛项目。华为初赛必须线下，完成度达到60%晋级，复赛选出10个决赛项目。25日9:00—9:05由杨幸主持开场，不安排领导致辞，9:05—9:15赞助单位代表发言；9:15—11:30两厅同步路演，兼报选手错开出场，下午统一颁奖。

天猫OPC孵化赛道 6 个获奖团队共 6,500 元：冠军 1 队 3,000 元、亚军 2 队各 1,000 元、季军 3 队各 500 元，另有周边和证书。华为产业落地赛道奖品与奖金 14,980 元，合计 27,500 元；天猫OPC孵化赛道 3,500 元物料预算不计入奖池。魔搭 130 份礼品用于现场抽奖；已发布线上转发抽奖保持独立入口和运营规则。奖励区桌面采用上方两块赛道奖励、下方三块额外权益：天猫与华为约 4∶6 分配宽度，奖级、名额与奖金紧凑对齐；智谱季卡、奇绩创坛 Token 支持、魔搭现场礼品在下方平铺。卡片内容按自然高度排列，不为等高拉大奖项间距；每份价值、每人额度与总奖池分别标注。手机端赛道卡依次展示，额外权益改为紧凑信息卡并连续滚动。

赛事与论坛分开报名。每位选手登录后使用共用姓名、学号、专业、年级资料，完善注册资料后自动带入对应报名表，已有报名回执优先保留原提交内容；通过华为产业落地赛道、天猫OPC孵化赛道两个 Tab 分别报名，手机号为联系字段，项目经历与科研经历必填；两赛道均必填队伍名称、选择是否为队长（是／否，不预选），并填写包含本人的 1—5 人队伍规模。每条赛道独立保存答案、提交时间及回执，切换 Tab 保留各自草稿；报名开放期间，已报名者可查看原答案、修改并重新提交，覆盖本人当前赛道的报名信息，保留报名编号和首次报名时间，不改另一赛道及已有作品、晋级记录；报名开放期间可分别撤销本人某一赛道报名，保留历史答案和作品但停止该赛道参赛资格及材料写入，再次报名可恢复，另一赛道不受影响；历史兼报仍保留两赛道资格，更新其中一条不覆盖另一条。这里只保存参赛快照，不按同名队伍推测成员关系。已有报名、仓库、发布赛题和其他赛事不被迁移覆盖。真实赛事表单保持标题与提交区常驻、字段独立滚动，手机输入字号至少 16px，提交区避开底栏。赛事群人数超过 200 人，赛事群入口展示用户提供的赛事成员微信二维码，并明确说明先添加成员微信、由成员邀请入群；不把个人微信码描述成直接入群码。介绍页删除首页重复报名、赛题、论坛与抽奖入口及说明性副文案；顶部报名采用荧光绿实底，抽奖采用强调色边框，保持持续可见。转发抽奖在当前页弹窗内选择活动、上传截图、提交并查看回执；只有一期活动时直接进入该期，关闭后保留原页面位置。旧抽奖深链仍可访问。弹窗顶部仅保留一句参与要求与官方推文链接，左侧奖品、右侧提交或回执，底部为提交截止、开奖时间和折叠规则；去掉重复活动标题、三步解释、倒计时和奖品重复合计。手机端奖品默认折叠。登录成功自动回到抽奖弹窗；驳回状态先展示原因，再由重新提交展开表单。

论坛页为 `/hackathon/2/forums`：技术论坛 18 日 9:00—11:30；创业论坛 25 日 13:30—16:05，地点为三墩元空间（宝港生活广场 C 座 6 楼）；上午另有决赛路演。华为产业落地赛道初赛选手须参加技术论坛，决赛选手必须参加决赛论坛。论坛面向校内外公众，可创建普通账号而不填写学生学号；赛事报名仍校验完整参赛资料。创业论坛报名按校内、校外切换：校内必填姓名、学号、专业、年级、手机号、想要提问的问题；校外仅必填姓名、手机号、单位或学校。当前只提供创业论坛新报名，历史技术论坛记录继续可读可取消。姓名、学号、专业、年级从已完善的账号资料自动带入，已保存的论坛报名信息优先；表单内修改仅属于此次论坛报名，不反向改写账号资料。开场截止报名，回执刷新恢复，重复提交更新同一账号同一场次记录，开场前可取消单场。管理员在论坛页导出 CSV，名单和联系信息不公开。签到后续另做，报名不代表已到场。

AI+X 报名成功后在介绍页显示报名编号与已保存信息，华为选手前往「赛题」页的「我的提交」。天猫校园不在本站提交，赛题页只显示组委会提供的二维码，扫描后进入官方提交渠道。华为初赛作品提交截止时间延长至 2026 年 10 月 18 日 18:15（北京时间），赛道独立窗口与总赛程保持一致；报名截止不变。华为材料按赛事、本人账号、赛道和轮次独立保存，不再共用一组仓库地址。正式提交须填写项目名称（最多 160 字符）；初赛填写 GitHub 仓库链接、魔搭社区部署链接或作品网址和作品说明书（功能讲解＋优秀运行结果），复赛在此基础上补交 Demo 运行录制视频，决赛提交 PPT／现场展示材料。草稿可暂不补齐。GitHub 只接受仓库首页 HTTPS 地址，华为作品网址接受自建服务器及其他平台的 HTTP/HTTPS 地址，不限制魔搭域名、部署路径或端口，未填写协议时补为 HTTPS；评委须能直接访问。天猫官方提交渠道、文案及原有校验保持不变。

| ---- | ---------------------------------- | -------------------------------------------------------------------------------------- |
| 初赛 | 本站不提交，显示二维码进入官方渠道 | 项目名称＋GitHub仓库＋魔搭社区部署链接或作品网址＋作品说明书（功能讲解＋优秀运行结果） |
| 复赛 | 本站不提交，显示二维码进入官方渠道 | 项目名称＋GitHub仓库＋魔搭社区部署链接或作品网址＋作品说明书＋Demo运行录制视频         |
| 决赛 | 本站不提交，显示二维码进入官方渠道 | PPT／现场展示材料                                                                      |

作品说明书只上传 PDF、PPT 或 PPTX，单文件上限 30 MB，须包含功能讲解和优秀运行结果；Demo 只上传 MP4、WebM 或 MOV，单文件上限 200 MB，不以外链替代。上传成功仅把附件加入当前草稿，保存草稿与正式提交是不同操作；只有正式提交后才成为评审依据。之后修改或保存草稿不覆盖已有正式快照，须再次正式提交才更新评审材料。截止后保留已保存记录和附件供读取，禁止继续保存、上传或正式提交。旧报名中的仓库链接仅作为历史资料，不自动转成任何轮次的正式提交。

后端同时检查该赛道报名、轮次起止时间和复赛资格；未被管理员明确授予该赛道复赛资格的账号不能上传或提交复赛材料。两赛道的队名、是否为队长和人数只作为报名快照，不据此合并账号、确认成员关系或授予队伍作品编辑权限；当前材料及资格仍归属于提交账号与赛道。历史报名缺少队长身份时保持未填写，不自动推断。提交不自动创建长期项目或公开作品。

报名、赛题发布、作品提交及成果发布各自有配置与权限判断。用户看到自己的提交状态，管理员看到当届完整报名和作品列表。后台报名名单按报名编号及账号关联实际分轮次提交，直接展示正式提交／仅草稿／暂无本站提交状态、项目名称及提交时间，可展开查看正式快照、最新草稿、仓库、部署链接和私有附件；可按提交情况筛选，报名 CSV 同步包含相应项目与材料信息。读取提交数据失败时明确报错，不显示为未提交；天猫官方渠道的数据不推测为本站提交。前台不会因为用户成功投稿就把该作品公开。

赛题页天猫只显示组委会二维码，不在本站提交；华为保留初赛、复赛、决赛。天猫OPC孵化赛道区分自主命题说明、推荐方向与正式发布赛题；推荐场景为法学、商务、医学、教育、宣传，统一按场景与用户、痛点、产品示例呈现，保留自由命题与作品形态说明。法学场景仅保留场景与用户、痛点、产品示例，不展示专项资源与账号积分权益。推荐场景不替代正式命题，不改动当前轮次的提交字段与赛事规则；华为产业落地赛道显示对应轮次的已发布命题。赛题发布和材料提交分别判断：华为赛题须管理员发布且到达 `challengeReleaseAt`（2026-10-18 13:00，Asia/Shanghai）后才显示查看与下载链接，未到时间不伪造内容。提交区区分读取中、读取失败可重试、未登录、未报名、未开始、未获复赛资格、未保存修改、已存草稿、正式提交和截止只读；失败保留输入，保存成功只在服务器确认后出现。并发修改发生版本冲突时，保留本地输入并读取服务器最新版本，由用户决定重新载入或继续修改，不静默覆盖。

### 作品、获奖与影像

公开作品需满足：**审核通过 + 同意公开 + 后台精选 + 当届成果已发布 + 未删除**。历史作品默认不自动精选；撤销精选或驳回后，从所有公开投影中同步退出。所有作品供有权限的后台管理，前台成果页只展示允许公开的精选。

AI+X「赛题」作为持续操作的工作页，不采用填写中滚轮翻屏。顶部采用紧凑的赛道与轮次选择区，桌面同排、窄屏两行。赛道选择位于内容顶部居中，轮次选择居于下一层；其下以图标加文字的紧凑信息栏展示本轮起止时间、地点及开放状态，不重复赛事名称与提交字段摘要。桌面左侧为“推荐场景”（华为为“本轮赛题”）、右侧为“提交作品”，两栏标题不编号。天猫的五个场景按 01—05 编号，独立卡片内统一呈现场景与用户、痛点、产品示例；根据内容区宽度采用两列或单列，手机单列连续阅读。场景上方按含义组织说明：自由命题区讲清选题范围，作品目标单列，作品形式用非交互标签呈现，运行演示、试点验证、用户反馈标明“鼓励提供”；选题方法以场景、用户、痛点、方案四问引导，桌面横排、手机两列。提交表单独立成框。字段直接说明所需材料，链接占整行，附件成组；保存草稿、正式提交和回执区分清楚。登录提示只在提交区出现，未报名或未晋级提示及相应操作靠近表单；读取失败保留重试入口。自由命题赛道的说明与推荐赛题待发布状态合并展示，不重复固定发布日期。状态与字段要求紧邻操作，历史仓库参考折叠放在提交区。轮次切换保留各自草稿，未登录时材料字段仍可见，由锁图标与紧凑登录蒙版提供入口。保存草稿与正式提交分开，回执显示正式材料和时间；附件提供上传进度、替换及鉴权下载，不能把上传完成当成正式提交。最终路演轮次只展示安排。命题须管理员勾选发布并达到对应赛道轮次开放时间才公开；天猫OPC孵化赛道初赛13日开始开发，18日开放材料提交，华为产业落地赛道初赛按 18 日 13:00 开放，其他届不继承本届规则。

现场照片页直接恢复直角化前的完整 `Gallery` 页面及看图弹层，分类栏复用 `415ae0b4a` 的展开分类交互并适配圆角，不重新拼装页面。保留原背景光晕、圆角和照片自然比例瀑布流；移除与赛事导航重复的页内大标题、小标题及大幅留白。顶部直接显示场景分类和明确的「批量上传照片」按钮，滚动时停留在赛事导航下方，切换场景回到照片区开头。栏目统一使用「现场照片」，仅展示和上传照片，不提供视频切换或视频上传入口；已有视频记录和文件保留。未开赛显示照片待发布状态，历史赛事无照片时显示暂无已发布照片，避免重复标题与全站摄影文案。各届共用模板，但只读取当届照片；场景以展开按钮切换，默认按场景标题分区，每区使用旧版圆角自然比例瀑布流，按可用列数分配照片以避免小分组右侧空列，分区标明照片数量（尚有分页时标明已加载数量），首届按致辞、开发、交流、颁奖顺序组织；分类、最新/精选与查看器保持轻量；首届历史影像遵循人工编排顺序，照片支持深链打开与键盘切换，大图同时显示场景及当前浏览序号。批量上传绑定当前赛事，可追加选图、预览、移除，最多 24 张且超限明确提示；批次标题可选，未填写时使用文件名。场景可从本届已有场景中选择，默认当前筛选场景；逐张显示上传与保存状态，只重试尚未成功的照片，保留审核流程；成果页汇集奖项、精选作品和赛后材料。作品详情属于当届成果，不另建项目中心。

### 后台报名查阅

后台报名默认展示当前赛事的人员名单与分布，赛事报名、论坛报名分别查看。统计按账号去重，兼报分别计入两赛道；已全部撤销的报名单列，不计入有效报名。论坛分别展示去重人数和场次报名数，旧报名缺少新必填字段时标明待补充。学校、专业、年级分布可点击筛选，统计范围始终为当前赛事，名单和导出遵循当前筛选。

名单采用可横纵滚动的紧凑表格，固定表头、勾选列和姓名列；支持表头排序、搜索完整嵌套答案、赛道／兼报／撤销／年级／专业／作品轮次与提交状态筛选、每页20／50／100条、列显隐与自动换行。列偏好只保存在本机，不缓存报名资料。点击姓名在详情区连续阅读完整回答、各赛道报名快照及分轮次作品材料，可复制手机号与学号，打开有效作品链接和鉴权下载附件。读取失败独立显示重试和未知状态，不当成零报名或未提交。

按填报队名查看时，仅将同一赛事、同一赛道、完整队名相同的报名分组，显示完整已报名成员、填报人数与队长；队长缺失／重复、人数填报不一致或与已报名人数不同的分组提示核对。人员筛选只用于定位分组，人数核对仍基于完整名单。队名分组不建立正式队伍关系，不根据同名认定项目归属。支持导出当前筛选结果或勾选人员，包含全部已填字段、历史赛道答案和作品正式快照，保留草稿区别，CSV防止公式执行，时间按北京时间显示。

赛事切换列表按开始时间由早到晚排列，每行左侧显示赛事名称与日期，右侧独立显示「即将开始／进行中／已结束」状态标签；进行中使用强调色实底，当前选中赛事另保留勾选标记。状态随当前时间计算，不因赛事被选中而改变。

只支持现行赛事路径；旧 `event/view/competition` 查询式赛事链接和 `showcase/works/projects` 别名不恢复。未知赛事或栏目显示未找到；作品和照片选择使用 `work/photo/mediaView` 等详情参数，媒体内部切换不占用外层栏目参数。论坛页、合作阵容页切换其他赛事回到介绍；其他赛事切换保留栏目，清理旧作品、照片和弹层选择。独立 `/media?event=<slug>` 保留影像档案用途。

手机通过顶部“更多”菜单进入浙客松，所有现行赛事栏目支持直接访问；页面按容器宽度自适应，不能仅按一张桌面稿固定像素。 AI+X 赛事、论坛与合作阵容在手机上采用连续阅读的海报式推文结构，不强制整屏翻页、不把桌面整页缩小。各章节以编号、标题与分界清晰划分，内容按手机宽度编排：赛制保留阶段与时间地点的对应关系，奖项按赛道独立成组，论坛以照片、姓名职务与分享主题形成完整区块。正文保留可读字号与完整身份，紧凑处理留白，内容自然滚动；报名入口、表单与赛事群保持可用。手机论坛报名短字段按两列组合，手机号与四道经历／开放题占整行，标签 14px、输入文字 16px、控件至少 44px，缩小空白而不缩小点击区域。桌面保持现有翻页、字号与版式，手机横屏继续连续阅读并利用横向空间。调整窗口、浏览器缩放或横竖屏切换后保留当前章节，不因页高变化跳到相邻页。内容高度扣除全局导航与底栏，低高度窗口允许自然滚动，定位报名避免标题被固定导航遮挡；检查 `320/390/820/1280/1440px` 及窄高、低高场景。日夜主题共用结构，首帧尊重减少动态效果，不能留下透明内容。

### 应验证的用户结果

- 不同届次的介绍、报名、赛题和成果不会串用；关闭或未发布内容无法通过深链绕过。
- 未登录或注册资料不完整时不能填写或提交赛事报名；资料保存后展开报名表，失败可重试，成功和刷新显示已有结果，重复请求可恢复，退出清空。
- 后台能管理完整报名/提交；公开入口只显示通过全部发布条件的内容，撤回后同步消失。
- 赛事切换、栏目返回、媒体查看与分享打开正确对象；空赛事、未关联媒体、加载失败有明确反馈。
- 全站导航、报名锚点、日夜主题和受影响尺寸实测通过。具体完成范围见状态文档。

## 技术设计

共享入口为 `HackathonEventRouter → HackathonWorkspace → HackathonEventContent`，复用 `HackathonRegistration` 与 `hackathon-event/` 组件。开发和生产采用同一入口，避免主题与数据读取分叉。

`shared/hackathonRoutes.json` 供前后端生成稳定路径；`settings.hackathon_schedule_config` 是日程配置真源，`shared/hackathonTemplateDefaults.json` 只提供代码默认值。发布同步赛事档案及必要旧设置投影，读取和写入均带明确届次标识。

`hackathon_forum_registrations` 按 event_key / user_id / forum_key 唯一保存私有论坛报名。正式迁移幂等建表及增补身份、学校、学生信息、项目／创业经历、科研经历、AI时代能力判断与创业投资提问字段。旧记录新增字段留空，不修改历史联系方式或补造答案；新提交校验手机号与当前身份对应的必填字段，校内不要求学校，校外不要求学号；校内外经历及开放题回答均保留。接口读取本人、原子保存所选场次、取消本人单场；管理员名单独立鉴权，响应 no-store。开闭时间来自共享 `hackathonForums.json`，服务端执行身份和截止验证。论坛账号不填学生资料，不授予管理员权限；之后赛事报名仍要求完整参赛资料。

AI+X 分轮次材料存入 `hackathon_submissions`，以 `event_key / user_id / track / stage` 唯一；`draft_json` 与 `submitted_json` 分别保存最新草稿和正式快照，各自记录时间。写入携带 `expectedVersion`，事务内比较版本并递增，冲突返回 409，不覆盖另一页面的新内容。`hackathon_submission_qualifications` 保存管理员对具体账号及赛道明确设置的复赛资格，默认未获资格；前台展示的时间、可操作状态与必填项来自服务端，保存和上传时再次校验。分赛道轮次窗口由 `event.program.trackStages` 承载，正式迁移幂等新增表及配置，保留旧仓库与其他届数据。

`hackathon_submission_files` 保存私有附件元数据，材料快照以 `bpFileId / demoFileId` 引用。上传检查大小、扩展名及文件签名，上传或附件登记失败时清理本次文件；替换附件保留旧文件，使已有正式快照继续可读。文件位于非公开的 `server/data/hackathon-submission-files`，不进入静态资源目录；下载仅允许本人或平台管理员，使用带登录鉴权的 API 返回附件，响应禁止缓存。管理员在 AI+X「提交与晋级」中按赛道和轮次查看正式材料与草稿，明确授予或取消复赛资格；管理名单和资格接口仅向平台管理员开放，不因前台隐藏入口而放宽权限。

`competition_works` 保存当届仓库和可空 HTTPS 部署证据；同一项目可参加多届，同一届只保留一条有效项目关联。`competitionWorkSelection` 正式迁移幂等增加 `featured`，默认 `0`，不自动精选旧记录。后台精选接口验证审核与公开授权，记录审计；驳回同步取消精选。

`competitionPublication.resultsPublishedSql` 把 `resultsVisible` 一致用于赛事、项目快照和公开个人作品查询。公开条件由后端执行，前端隐藏卡片不能代替它。

图片本体保存在 `photos`，`competition_media_links` 以 `archive/highlight` 表达当届归档与精选用途，影像通过受控嵌入复用媒体能力。旧 `competition_media` 的处理需以实际引用和数据核验为前提。报名、媒体上传和发布沿用账号、审核、审计与正式迁移，不新增孤立身份或存储体系。
