# 容器运行与备份

现网由 Caddy 和 PM2 运行。Docker/Compose 为可选独立环境，基础镜像使用 Node.js 22，目标分别为 production 和 development。需要 Docker Compose v2.24 或更高版本。

## 启动前

按 [README](../../README.md) 准备私有的 server/.env，至少配置随机生成的 SECRET_KEY。环境文件在运行时读取，不进入 Git 或镜像构建上下文。

生产数据库、上传、日志、备份使用命名卷 data、uploads、logs、backups；开发数据使用独立的 dev-data、dev-uploads。旧 Docker 环境的宿主机 ./data、./uploads 不会自动迁入命名卷，切换前须停止写入、备份并明确导入目标卷。现行 Caddy/PM2 数据不参与这些卷操作。

## 运行

```bash
docker compose --env-file server/.env up --build -d app
curl --fail http://127.0.0.1:5181/api/health
docker compose --env-file server/.env logs --tail 100 app
```

生产产物目录为 /app/dist，共享定义为 /app/shared，后端工作目录为 /app/server。进程使用非 root 用户，宿主机只在回环地址开放 5181；容器进程显式监听 0.0.0.0，避免环境样例中的本地回环监听覆盖容器配置。HTTPS 沿用外部 Caddy。旧 Nginx profile 引用的配置目录不存在，已移除。

默认 CORS 客户端包括正式裸域、www 和 iOS 的 `capacitor://localhost`。自建容器可通过 `CORS_ALLOWED_ORIGINS` 显式指定自己的来源。现网 Caddy/PM2 发布会把旧 CORS 别名合并到同一白名单，保留额外客户端、移除历史 IP，并补齐正式 Web/iOS 来源；环境文件原子替换并由已有发布备份、失败恢复流程保护，不改变数据库、端口或业务密钥。

后台任务默认关闭。启用采集、定时任务前完成对应私有配置，再显式设置 BACKGROUND_TASKS_DISABLED=0。

开发环境单独启动：

```bash
docker compose --env-file server/.env --profile development up --build dev
```

前端使用 5180，后端使用 5181，Vite 代理 /api 和 /uploads 到容器内后端。开发与生产目标占用同一后端端口，应分别启动。开发目标关闭后台任务，绑定源码并使用容器内 node_modules。

## 备份

非容器环境在仓库根目录执行：

```bash
npm --prefix server run backup
npm --prefix server run backup -- --database /absolute/source.sqlite --directory /absolute/backups
```

默认读取 server/.env 和环境变量 DATABASE_FILE、BACKUP_DIR；未指定时使用 server 工作目录下的 database.sqlite 和 backups。备份复用发布工具的 VACUUM INTO 和 quick_check，包含已提交 WAL；源库缺失时失败，不生成空源库或覆盖已有快照。

容器执行一次备份：

```bash
docker compose --env-file server/.env --profile with-backup run --rm backup npm run backup
```

持续备份服务每 24 小时执行一次，失败后退出并由 Compose 重启策略重启。源卷只读，快照保存在 backups 卷，不自动删除旧文件。

失效的 optimize-images 命令已移除，现有 imageProcessor 保留，未提供覆盖已有上传文件的批处理命令。

## 验证

```bash
docker compose --env-file server/.env config --quiet
bash scripts/check-containers.sh
```

第二条命令使用随机测试密钥、独立 Compose 项目及临时卷，实际构建两个目标，检查静态页、健康接口、开发代理、共享目录、重建后数据保留及备份。结束仅清理该检查创建的项目卷。检查需要本机 5180/5181 空闲，已作为 GitHub Actions 构建和部署的前置条件。
