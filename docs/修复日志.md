## 2026-10-21｜处理注册超时和收藏校验

### 注册请求不再一直挂起

用浏览器复现后发现：注册服务一直不返回时，提交按钮会持续加载。于是在 [AuthContext](../src/context/AuthContext.jsx) 的注册请求里设置了 15 秒超时，超时后恢复按钮、保留输入，并补上中英文提示。注册请求继续禁止自动重试，避免网络异常时重复提交。提示也没有断言“注册一定失败”，因为服务端可能已经处理成功，只是响应没有及时回来。

这部分使用 JavaScript / JSX、React、Axios，提示文本维护在 JSON 词典中。[注册超时测试](../e2e/registration-timeout.spec.js)用 Playwright 和本机隔离 HTTP 服务模拟挂起、错误响应、再次提交成功及断线，4 项测试通过。提交：[`4102253`](https://github.com/elgoog577215-beep/ZJU_Platform/commit/4102253)。

### 收藏前检查目标和权限

[收藏接口](../server/src/controllers/favoriteController.js)原先对目标的检查不够完整。这次补上类型白名单、合法 ID、目标存在性和查看权限判断，检查通过后才允许新增收藏。另外保留了一个必要行为：原来收藏的内容即使后来被删除或下架，用户仍然能取消收藏。

这部分使用 JavaScript、Node.js、Express 和 SQL，沿用已有 JWT 鉴权及权限规则，没有修改数据库结构。[新增测试](../server/tests/favorite-controller-validation.test.js)使用真实接口逻辑和内存 SQLite，通知与队列使用隔离替身；连同已有权限测试共 22 项通过，覆盖非法参数、不可见目标、正常收藏、取消收藏和部分并发失败情况。没有拿生产账号或生产数据库做写入验证。提交：[`3c42a2f`](https://github.com/elgoog577215-beep/ZJU_Platform/commit/3c42a2f)。

## 2026-10-22｜修正四组配置

### Docker 和 Compose

Docker 基础镜像从 Node.js 18 调整到 22。前端阶段安装构建工具，后端单独安装运行依赖，补齐 dist、server 和 shared 的目录；生产进程使用非 root 用户，健康检查统一到 5181。新增 .dockerignore，排除环境文件、数据库、上传、依赖目录和签名材料。

容器实测发现 sqlite3 预编译包要求的 glibc 高于基础镜像。生产和开发构建阶段使用 Python、make、g++ 编译 sqlite3，并立即检查模块加载，保证原生扩展与运行环境一致。
